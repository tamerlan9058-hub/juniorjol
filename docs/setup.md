# Запуск и модерация

Чек-лист для владельца репозитория. Всё делается в веб-интерфейсе GitHub, на компьютере ничего ставить не нужно.

## 1. Один раз при запуске (≈30 минут)

1. **Сделать репозиторий публичным:** Settings → General → Danger Zone → Change visibility → Public. Для публичных репозиториев GitHub Actions бесплатны.
2. **Переименовать** репозиторий в `juniorjol` (Settings → General → Repository name). Ссылки со старого имени GitHub перенаправит сам. После переименования поменяйте поле `repo` в `config.json`.
3. **Основная ветка:** Settings → Branches → переименовать текущую ветку по умолчанию в `main`. Автоматизация от имени ветки не зависит.
4. **Описание и темы:** на главной странице репозитория ⚙️ рядом с About. Описание — «Стажировки и junior-вакансии в IT Казахстана». Темы: `kazakhstan`, `internships`, `jobs`, `junior`, `almaty`, `astana`.
5. **Метки:** Actions → «Настройка меток» → Run workflow.
6. **Уведомления:** Watch → All Activity, чтобы получать письма о новых заявках.
7. **`config.json`:**
   - `contact_email` — рабочий адрес проекта (заведите отдельный, личный не публикуйте);
   - `telegram_channel` — например `@juniorjol`;
   - `kaspi_pay_link` — появится после открытия ИП и подключения Kaspi Pay (Kaspi Pay → Удалённая оплата → Ссылка для оплаты);
   - `launch_promo` — `true`, пока Featured бесплатный для первых работодателей.

   После правки config.json запустите `python3 scripts/board.py render` или просто дождитесь следующей публикации — тарифы в `docs/employers.md` обновятся сами.

## 2. Сайт на GitHub Pages (по желанию)

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Settings → Secrets and variables → Actions → Variables → New variable: `PAGES_ENABLED` = `true`.
3. Actions → «Сайт» → Run workflow. Адрес сайта появится в Settings → Pages.

## 2а. Чтобы сайт находили в Google и Яндексе (≈10 минут)

Сайт уже готов для поиска: вакансии вписаны прямо в HTML, есть карта сайта и превью для ссылок в Telegram и WhatsApp. Осталось сообщить о нём поисковикам.

1. **Google:** откройте [Search Console](https://search.google.com/search-console) → «Добавить ресурс» → **Префикс URL** → `https://tamerlan9058-hub.github.io/juniorjol/`.
   Способ подтверждения — **Тег HTML**: скопируйте из тега значение `content="…"` и вставьте его в `config.json` в поле `google_site_verification`. Через пару минут (после пересборки сайта) нажмите «Подтвердить».
   Затем слева «Файлы Sitemap» → впишите `sitemap.xml` → «Отправить».
2. **Яндекс:** [Яндекс Вебмастер](https://webmaster.yandex.ru/) → добавить сайт → подтверждение **Мета-тегом** → значение `content` в поле `yandex_verification` в `config.json`. Затем «Индексирование → Файлы Sitemap».
3. **Ссылки на сайт** — главное для поиска: README репозитория, описание Telegram-канала, посты в чатах вузов, профиль LinkedIn. Чем больше мест ссылается на сайт, тем быстрее он поднимется.

Первые страницы появятся в поиске через 1–4 недели. Основной поток студентов на старте всё равно придёт из Telegram и чатов, а не из поиска.

## 3. Telegram-канал (рекомендуется — студенты живут там)

1. Создайте публичный канал, например `@juniorjol`.
2. В [@BotFather](https://t.me/BotFather): `/newbot` → получите токен бота.
3. Добавьте бота в канал администратором с правом публиковать сообщения.
4. Settings → Secrets and variables → Actions:
   - **Secrets** → `TELEGRAM_BOT_TOKEN` = токен бота (только в секреты, никогда в код!);
   - **Variables** → `TELEGRAM_CHAT_ID` = `@juniorjol`.

Новые вакансии будут публиковаться в канале сразу после одобрения, а по понедельникам туда будет уходить дайджест недели.

## 4. Ежедневная модерация (5–10 минут)

Откройте Issues с меткой **ready-for-review** — бот уже проверил, что заявка заполнена правильно.

| Ситуация | Что сделать |
|---|---|
| Вакансия настоящая, ссылка открывается, условия нормальные | Поставить метку **approved** — вакансия опубликуется, issue закроется сам |
| Что-то не так | Написать в issue, что поправить. После правки бот перепроверит; затем снять и снова поставить **approved** |
| Спам, мошенничество, платная «стажировка» | Закрыть issue с комментарием |
| Работодатель оплатил Featured | Поставить метку **paid**. Если вакансия уже опубликована — она сразу поднимется наверх; если нет — станет Featured при публикации |
| Заявка «Закрыть вакансию» | Проверить и поставить **approved** — вакансия уйдёт в архив |
| Работодатель без GitHub прислал вакансию в Telegram или на почту | Создайте заявку через форму сами и одобрите её |

Метки обрабатываются только от владельца репозитория. Помощников-модераторов можно добавить: дайте им доступ Triage (Settings → Collaborators) и создайте переменную `MAINTAINERS` с JSON-массивом логинов, например `["login1","login2"]`.

## 5. Если что-то сломалось

- **Красный значок в Actions:** откройте упавший запуск — в логе будет понятная ошибка. Чаще всего это кривой `config.json` (проверьте запятые и кавычки).
- **Ежедневная очистка перестала работать:** в публичных репозиториях GitHub выключает запуски по расписанию после 60 дней без активности. Actions → «Ежедневное обслуживание» → Enable workflow.
- **Проверить логику локально:** `python3 -m unittest discover -s tests -v`.
